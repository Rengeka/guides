# ADR Status

### What is ADR Status?

ADR Status is an indicator of the current state of an architectural decision described in a record. The status helps quickly understand whether a decision is a proposal, an active rule, outdated, or rejected. It's a key element for managing the decision lifecycle and keeping documentation up-to-date.

### Why Are Statuses Important?

1. Clarity and Transparency: All project participants understand which decisions are already made and active, and which are just ideas.

2. Change Management: Allows tracking architecture evolution. It's clear which decisions were replaced by new ones and why.

3. Communication Efficiency: New team members or external auditors don't need to read the entire document to understand its authority. A glance at the status is enough.

4. Focus on Current State: Helps avoid situations where teams follow outdated recommendations because a document wasn't marked as changed.

### Core Statuses and Their Meaning

| Status | Description | When to Use | Example File Name|
|--------|-------------|-------------|------------------|
| Proposed | The decision is suggested but not yet reviewed or approved. This is a draft for discussion. | You've documented an idea and are submitting it for architect/team review. | 0001-proposed-use-graphql-api.md|
| Accepted | The primary active status. The decision has been reviewed, approved, and accepted for implementation/use. This is an active architectural rule. | The decision passed discussion, received approval from responsible parties (Deciders), and is now a standard. | 0001-accepted-use-graphql-api.md |
| Rejected | The proposal was considered but not adopted. It's important to keep such records to avoid revisiting already discussed and unsuitable options in the future. | After discussion, the team decided this option doesn't meet key criteria. | 0001-rejected-use-soap-api.md |
| Deprecated | The decision was accepted and used but is now considered outdated. It's no longer recommended for new development but may be supported in legacy code. | A new, better technology emerged or requirements changed. | 0001-deprecated-use-angularjs.md |
| Superseded | The decision was replaced by another, newer ADR. This is a direct and explicit reference to evolution. The most accurate way to indicate a record is obsolete. | You created a new ADR (e.g., 0005-accepted-use-react-over-angular.md) that explicitly replaces the old one. In the old record, set status to Superseded and add a link to the new one. | 0001-superseded-use-angular.md |
| Archived (optional) | The record is preserved for history but has completely lost relevance (e.g., the project it related to is closed). Often used with Rejected or Superseded. | You want to remove the record from the active list but not delete it from the repository. | 0001-archived-rejected-use-mongodb.md |

### ADR Lifecycle:

```
          [Proposed]
              │
              ▼ (Review)
        ┌─────┴─────┐
        ▼           ▼
   [Accepted]   [Rejected]
        │
        ▼ (New Decision)
   [Superseded] ────► [New ADR with accepted status]
        │
        ▼
   [Deprecated]
        │
        ▼
   [Archived] (Optional)
```

### Practical Recommendations

Initialization: All new ADRs are created with the Proposed status.

Transition to Accepted: Occurs after formal or informal approval by responsible parties (Deciders). Their names should be listed in the record.

Reference for Superseded: Always include a reference to the new ADR in the Links field or a special Superseded-by field.

    Superseded by: [ADR-0005](0005-accepted-use-react-over-angular.md)

Don't Delete Rejected Records: These records are invaluable. They preserve context and reasons for rejection, saving time for future developers.

Include in Filename: Many practices recommend including the status in the filename (e.g., 0001-accepted-...). This allows immediate visibility of the decision's state in the file manager or list.

Automation: Extensions (like ADR Manager for VSCode) or tools like adr-tools often have commands for convenient status changes.
